# ADR-0009: Make every screen a child of the screen that opened it, addressed by a route with one text form

- Status: Proposed
- Date: 2026-10-14
- Related: `docs/specs/navigation.md` (approved 2026-10-14), #67, ADR-0006, ADR-0007, ADR-0008

## Context

ADR-0006 made navigation state in the root module and deferred its mechanics to the navigation epic, #67, with real screens to try them on. M2 built the first pieces: a root holding one child, the sidebar, and a pane that is a placeholder, with the duties of a parent written out once in the root. The owner's one concern with the module architecture is the root growing into a god module as screens arrive; and links, restoration, more than one window on the Mac and the web's address bar all need an address for every screen that can be open. The brainstorm and the spec's sections 1 to 5 and 7 hold the discussion.

## Decision

Every screen is a child of the screen that opened it: the root holds the first screens and nothing below them, every screen holds the screens it opens, and the tree of live modules is the navigation state. The duties of a parent are written once beside the contract, in the `FeatureModule` target, which starts depending on `TodoCore`: a protocol for an addressed module, which requires a `Route` with a head and a tail, an `init(store:route:)` that throws `StoreError`, a `var route` assembled from its state and its children's routes, and an `Event` that spells `.route(Route)`; and a generic seat a parent holds each child in, which creates the child from a route, sends it `.created` and hands the answer back, compares heads on `.route` and keeps, replaces or drops the child, and gives the parent the child's route and model. A parent still writes per child its `Model` field, its `UserAction` case, one line forwarding the child's actions, one forwarding `.changed`, and its reaction to the child's `Output` in a `switch` with no `default`. Inside a module, navigation has one entrance, apply a route: a tap, a link, a relaunch and the way back are each a route applied, and applying is a reconciliation by head and never a rebuild, so session state survives what did not change; the head of a live module never changes, and a module that receives `.route` looks at the tail alone. A route is a plain value and not a model; it may carry what a screen opens with, in its tail and never in its head, read once in `init(store:route:)` and never written back, and it carries no session state. It has one text form, a path with a query written and read by one codec in the core, which is the deep link, the state a window is restored from and the web's route; the composition root strips the platform's wrapping, a scheme or a site, and reads the string with the codec, and a string that does not read is refused with a typed error naming the segment. A request a parent cannot serve, it re-emits as an output of its own, under its own name. A window is a tree of modules with its own root and its own host, and a process is one store and one composition root that creates a host per window and hands every `ChangeSet` to every live host, under the rule that a module never writes to the store in answer to `.changed`; whether an idle host takes the change set inside the other window's event, which the spec chooses, or on the next turn of the main actor is the plan's probe to settle. The root's first output to the platform is `.openWindow(Route)`, so the host's output is no longer `Never`. Quick entry is the root's child on every platform; whether a child is drawn pushed, in a column or in a sheet is rendering, and no SwiftUI container reaches the core or an ADR. The names of the protocol and the seat are settled by a compiler probe against SwiftUI and Foundation before any task uses them.

Alternatives. A flat `path` of screens in the root with modals beside it lost because the root would grow with every screen and hold the transition table of the whole app, and the core would have to tell a push from a modal. A coordinator service modules call to navigate lost, as in ADR-0006, because the set of open screens would leave the model. Navigation in the views with `NavigationLink` and `@State` lost because a view deciding what opens is a view holding logic, and none of it runs on wasm32. One root per process holding every window in a table lost because every action and model would carry a window id and iPhone would carry the table for its one window. Quick entry as a window of its own on the Mac lost because the module's home would depend on the platform. Text routes handled inside modules lost because every module would parse, and a typo would be found at runtime. A `Codable` route lost because it is a second serialisation beside the text form, with no test on wasm32 and with a conformance ADR-0006 says comes with the wire; the window's value is the text form. The view parsing the URL it receives lost because a parser in a view is logic in a view, and it would exist once per platform. The child's model as the navigation item lost because SwiftUI hashes the item and a model has hundreds of rows. Replacing the module tree on every `.route` lost because a link into an open task would lose the session state of everything on the way.

## Consequences

Easier: every screen is addressable by construction, since an addressed module cannot exist without a route; a deep link, restoration after a relaunch and the web's address bar are one codec and one entrance, tested on the host and on wasm32 before any platform draws; a parent's code per child is a handful of lines and the root does not grow when a grandchild learns a new screen; a second window on the Mac and the one window of iPhone are the same code; a tap and a link cannot open different things because they are the same code.

Harder: every addressed module carries a route type and its reconciliation, which is a type and a few lines per screen; the fan-out of a change set to every window rests on a rule that nothing enforces but a test; every parent forwards each event of the world in a line of its own, until a third such event may fold them into one case, which the spec leaves open; a route that names a gone entity has to be answered with what still exists and a sentence, screen by screen.

Constrained: no module navigates except by applying a route, and no view sends one or parses a URL; no module writes to the store in answer to `.changed`; the text form is the only serialisation of navigation state, and session state never enters it; a window is one host and one root, and the store is one per process; a parent learns a child's choice only through its output, as ADR-0006 already requires. Reversing this decision means flattening the tree back into the root, which is cheap for the three screens of this epic and a rewrite of every parent afterwards.
